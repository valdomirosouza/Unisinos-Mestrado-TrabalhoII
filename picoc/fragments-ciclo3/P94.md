### P94 — Design of a Security Framework for Multi-Agent Systems Based on Model Context Protocol in SOC Environments

**Raciocínio:** A Population é literal do abstract (p. 1) e da §3.1 (pp. 5–7): "MCP-based multi-agent SOC pipelines" — um pipeline sequencial triage–enrichment–response com três agentes LLM (GPT-4o mini, §3.3/Tabela 4, pp. 16–17), memória compartilhada persistente e conexão a um SIEM Wazuh real (4.14.0) via MCP server custom, operando em apoio a analistas Level 1 de SOC (§1, p. 2). A Intervention é o framework de segurança proposto (§3.2, pp. 7–14): middleware gateway que intercepta toda comunicação agente↔MCP server, com validador de registro de ferramentas na fase de conexão (scan de descrições, namespace ownership, pinning SHA-256) e cinco camadas de execução (L1 access control/RBAC, L2 rate limiting, L3 input validation, L4 output validation, L5 audit log append-only), mais controles transversais (failure opacity, session UUID, verificação supply chain, autenticação de canal MCP) — paradigma de guardrails determinísticos (pattern matching, não LLM-based) sobre pipeline multiagente sequencial com HITL (o response agent nunca executa ações diretamente; propose_wazuh_rule só gera proposta para revisão do analista, §3.1, p. 6). A Comparison se aplica porque há comparação empírica executada: o harness toma "a baseline measurement... without the security framework" (§3.5.1, p. 19) e a demonstração full-pipeline (§4.2, pp. 23–24) contrasta a condição desprotegida (baseline, 4 ferramentas maliciosas admitidas no namespace) com a condição protegida (2 rejeitadas na conexão, 2 bloqueadas downstream), com outputs operacionais benignos idênticos entre condições. Os Outcomes são quantitativos e ancorados: threat model de 35 vetores de 5 taxonomias, 29 cobertos pelo middleware (Tabela 2, §3.2.8, p. 13); 6 suítes (T00–T05), 25 instâncias únicas de ataque × N=20 → 600/600 decisões de bloqueio corretas, 0 ataques passados, 0 falsos bloqueios no conjunto avaliado (Tabela 12, §4.1, p. 23); overhead local agregado <0,6 ms por chamada (<30 µs com schema pré-compilado; JSON Schema 546,6 µs → 11,4 µs, Tabela 13, §4.3, p. 24); limites: 4 técnicas de ofuscação (base64, homoglyph, espanhol, paráfrase) evadem 100% dos controles léxicos (0/4 bloqueados, Tabela 14, §4.4, p. 25) e 7/8 inputs benignos attack-like geram falsos positivos (Tabela 15, §4.5, p. 26). Não há métricas MTTD/MTTR nem de carga operacional — o benefício medido é eficácia de segurança do copiloto agentic, não tempo de resposta a incidentes. O Context é SOC/incident triage em testbed de laboratório (Vagrant + Docker Compose com segmentação de rede, §3.3, pp. 15–16) contra SIEM Wazuh real, com supervisão humana obrigatória para ações consequentes. Tipo: estudo primário (proposta de framework + avaliação experimental controlada). Aderência: RQ1 (autonomia agêntica com planejamento, uso de ferramentas e HITL, §1/§3.1), RQ2 (arquitetura multiagente MCP com guardrails, memória e observabilidade via audit log, §3.1–3.2), RQ3 parcial (evidência quantitativa de eficácia/overhead, §4.1/§4.3, mas sem MTTD/MTTR), RQ4 (threat model, riscos de tool poisoning/prompt injection/confused deputy e limites dos controles léxicos, §3.2.8/§4.4–4.5/§5) e RQ5 (lacunas: detecção semântica, topologias não sequenciais, avaliação cross-model, memória escalável, tamper-evidence do log, §5–§6).
